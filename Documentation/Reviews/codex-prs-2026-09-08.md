## Findings

### P1 — A timeout must not certify incomplete scoring data as ready

New in #7, now included in #6. Relevant code: [RoundSession.swift:430–446](https://github.com/kylebeard56/Hackers-Compete-iOS/blob/ceec4ed26d799ccc890246b1823d4e3e27a09bcd/Hackers/Core/Round/RoundSession.swift#L430) and [LiveRound.swift:357–369](https://github.com/kylebeard56/Hackers-Compete-iOS/blob/ceec4ed26d799ccc890246b1823d4e3e27a09bcd/Hackers/Features/Round/LiveRound/LiveRound.swift#L357).

At 12 seconds, `completeInitialLoadTrackingIfTimedOut()` sets `isScoringSnapshotReady = true` regardless of which listeners have delivered data. `restoreDurableRoundContextIfNeeded()` additionally allows the timeout flag to bypass the matching-round/nonempty-participants guard. It then marks restoration complete and persists the displayed hole.

Two concrete failure paths follow:

1. **Round and participants are cached, but scores have not arrived.** After 12 seconds, scoring controls open with an empty or incomplete score collection. Existing scores can appear unentered. `setScore` uses a deterministic player/segment/hole document ID and writes the selected strokes; it does not independently require initial score readiness. A user can therefore replace a score they never saw. See [score write path](https://github.com/kylebeard56/Hackers-Compete-iOS/blob/ceec4ed26d799ccc890246b1823d4e3e27a09bcd/Hackers/Features/Round/LiveRound/LiveRoundViewModel.swift#L4594).
2. **The round document itself arrives after the timeout.** The view marks restoration complete using the placeholder snapshot. When the actual round ID arrives, `resetRoundScopedStateIfNeeded` clears the restored hole and resets the current index, but the view’s `hasRestoredScoringContext` prevents restoration from being attempted again. The resumed hole can change and be persisted over the user’s saved selection. See [round-scoped reset](https://github.com/kylebeard56/Hackers-Compete-iOS/blob/ceec4ed26d799ccc890246b1823d4e3e27a09bcd/Hackers/Features/Round/LiveRound/LiveRoundViewModel.swift#L4925) and the view guard above.

**Evidence:** A standalone Swift probe compiled and ran the exact readiness enums/methods from this head. It confirmed the normal warm transition succeeds after the scoring listener arrives. It also confirmed `ready=true` with `.scoring` still missing after timeout, and that an empty snapshot passes the view’s restoration guard. The downstream scoring/persistence consequences were verified by tracing callers; no live database writes were performed as a reproduction.

**Required correction:** Keep timeout/error state separate from successful readiness. Present an error/retry or unavailable state, keep score editing disabled, preserve the saved resume state, and restore the hole only after the correct round and required listener snapshots arrive. The new timeout test currently asserts that missing data becomes “ready”; revise that expectation and cover delayed scoring plus late round-document arrival.

```swift
// Current timeout behavior
isScoringSnapshotReady = true

// Desired timeout behavior
// Record/display a recoverable timeout; leave scoring readiness false.
didTimeOutInitialLoad = true
```

The UI should require both genuine readiness and a usable matching snapshot; remove the timeout alternative from the restoration guard. Merely keeping readiness false without adding an error/retry UI would restore the old indefinite spinner, so those changes belong together.

### P2 — Radar chart still exaggerates zero/small categories

Unchanged since the first review, explicitly deferred in PR #7. Relevant code: [FullScorecardView.swift:2628–2632](https://github.com/kylebeard56/Hackers-Compete-iOS/blob/ceec4ed26d799ccc890246b1823d4e3e27a09bcd/Hackers/Features/Round/LiveRound/Accessory/Sheets/FullScorecardView.swift#L2628).

Zero counts are drawn at 12% radius. Positive values get a 20% offset: one occurrence against a maximum category count of ten renders at 28% radius instead of 10%. Labels are correct, but the shape misrepresents their proportions.

Keep the five-category layout, colors, and labels. Use proportional values and a separate empty state or markers for visibility.

```swift
// Current
return count == 0 ? 0.12 : 0.2 + CGFloat(count) / CGFloat(maximumCount) * 0.8

// Proportional
return CGFloat(count) / CGFloat(maximumCount)
```

This is lower priority than the scoring-readiness issue and can be consciously deferred; it is still unresolved.
